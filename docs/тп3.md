### 2. Спецификация физических таблиц и ограничений целостности

#### 2.1. Справочные таблицы (НСИ)
1. **`warehouse.uom`** — справочник ОКЕИ (единицы измерения).
2. **`warehouse.sku`** — номенклатура ТМЦ. Ограничение: `safety_stock >= 0`, `unit_weight_kg > 0`.
3. **`warehouse.warehouse_zone`** — физические зоны склада (`A`, `B`, `C`, `Q`, `EXP`).
4. **`warehouse.storage_cell`** — адресные ячейки. Ограничение: `max_weight_kg > 0`, `max_volume_m3 > 0`.
5. **`warehouse.department`** — цеха-потребители (МЦ-1, СЦ-2, ЦПО).
6. **`warehouse.supplier`** — внешние контрагенты. Ограничение формата ИНН (`10` или `12` цифр).

#### 2.2. Таблицы учёта движения и входного контроля
7. **`warehouse.app_user`** — учётные записи сотрудников завода.
8. **`warehouse.user_role`** — роли доступа пользователей (RBAC).
9. **`warehouse.receipt_order`** — заголовок приходной поставки (форма М-4).
10. **`warehouse.batch`** — партии материалов. Ограничение: `initial_quantity > 0`, `current_quantity >= 0`.
11. **`warehouse.qc_protocol`** — акты входного контроля заводского ОТК.
12. **`warehouse.location_balance`** — баланс ячеек. Ограничение: `physical_quantity >= reserved_quantity`, `reserved_quantity >= 0`.

#### 2.3. Таблицы отпуска, инвентаризации и аудита
13. **`warehouse.issue_request`** — заголовок электронного требования-накладной М-11.
14. **`warehouse.request_item`** — товарная спецификация требования. Ограничение: `requested_quantity > 0`.
15. **`warehouse.request_allocation`** — декомпозиция бронирования по ячейкам и партиям.
16. **`warehouse.stock_movement_log`** — неизменяемый журнал складских проводок.
17. **`warehouse.inventory_sheet`** — описи циклической инвентаризации (ИНВ-3).
18. **`warehouse.inventory_item`** — результаты пересчёта позиций.

### 3. Полный SQL-скрипт миграции (Flyway `V1__Initial_Schema.sql`)

```sql
-- Создание рабочей схемы
CREATE SCHEMA IF NOT EXISTS warehouse;

-- 1. Единицы измерения (ОКЕИ)
CREATE TABLE warehouse.uom (
    id SERIAL PRIMARY KEY,
    code VARCHAR(10) NOT NULL UNIQUE,
    name VARCHAR(50) NOT NULL,
    description VARCHAR(100)
);

-- 2. Номенклатурный классификатор (SKU)
CREATE TABLE warehouse.sku (
    id BIGSERIAL PRIMARY KEY,
    article VARCHAR(64) NOT NULL UNIQUE,
    name VARCHAR(255) NOT NULL,
    category VARCHAR(50) NOT NULL,
    material_grade VARCHAR(100),
    standard_code VARCHAR(100),
    uom_id INT NOT NULL REFERENCES warehouse.uom(id) ON DELETE RESTRICT,
    unit_weight_kg NUMERIC(12, 4) NOT NULL CHECK (unit_weight_kg > 0),
    safety_stock NUMERIC(12, 3) NOT NULL DEFAULT 0 CHECK (safety_stock >= 0),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 3. Функциональные зоны склада
CREATE TABLE warehouse.warehouse_zone (
    id SERIAL PRIMARY KEY,
    code VARCHAR(10) NOT NULL UNIQUE,
    name VARCHAR(100) NOT NULL,
    zone_type VARCHAR(30) NOT NULL CHECK (zone_type IN ('STORAGE', 'RECEIVING_QUARANTINE', 'HAZARDOUS', 'DISPATCH'))
);

-- 4. Адресные ячейки склада
CREATE TABLE warehouse.storage_cell (
    id BIGSERIAL PRIMARY KEY,
    address_code VARCHAR(32) NOT NULL UNIQUE,
    zone_id INT NOT NULL REFERENCES warehouse.warehouse_zone(id) ON DELETE RESTRICT,
    rack_number INT NOT NULL,
    section_number INT NOT NULL,
    tier_number INT NOT NULL,
    position_number INT NOT NULL,
    max_weight_kg NUMERIC(10, 2) NOT NULL CHECK (max_weight_kg > 0),
    max_volume_m3 NUMERIC(8, 3) NOT NULL CHECK (max_volume_m3 > 0),
    cell_status VARCHAR(20) NOT NULL DEFAULT 'FREE' CHECK (cell_status IN ('FREE', 'PARTIALLY_OCCUPIED', 'FULL', 'BLOCKED')),
    CONSTRAINT uq_cell_coordinate UNIQUE (zone_id, rack_number, section_number, tier_number, position_number)
);

-- 5. Подразделения (цеха-потребители)
CREATE TABLE warehouse.department (
    id SERIAL PRIMARY KEY,
    code VARCHAR(20) NOT NULL UNIQUE,
    name VARCHAR(150) NOT NULL,
    responsible_person VARCHAR(150) NOT NULL
);

-- 6. Пользователи системы
CREATE TABLE warehouse.app_user (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(64) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    full_name VARCHAR(150) NOT NULL,
    department_id INT REFERENCES warehouse.department(id) ON DELETE SET NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 7. Роли пользователей (RBAC)
CREATE TABLE warehouse.user_role (
    user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE CASCADE,
    role_name VARCHAR(50) NOT NULL,
    PRIMARY KEY (user_id, role_name)
);

-- 8. Поставщики
CREATE TABLE warehouse.supplier (
    id BIGSERIAL PRIMARY KEY,
    inn VARCHAR(12) NOT NULL UNIQUE,
    name VARCHAR(255) NOT NULL,
    contact_info TEXT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 9. Приходный ордер (форма М-4)
CREATE TABLE warehouse.receipt_order (
    id BIGSERIAL PRIMARY KEY,
    doc_number VARCHAR(64) NOT NULL UNIQUE,
    supplier_id BIGINT NOT NULL REFERENCES warehouse.supplier(id) ON DELETE RESTRICT,
    incoming_invoice_num VARCHAR(64) NOT NULL,
    incoming_invoice_date DATE NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'REGISTERED' CHECK (status IN ('REGISTERED', 'IN_INSPECTION', 'COMPLETED', 'REJECTED')),
    created_by_user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE RESTRICT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 10. Партии материалов (Batch)
CREATE TABLE warehouse.batch (
    id BIGSERIAL PRIMARY KEY,
    receipt_order_id BIGINT NOT NULL REFERENCES warehouse.receipt_order(id) ON DELETE RESTRICT,
    sku_id BIGINT NOT NULL REFERENCES warehouse.sku(id) ON DELETE RESTRICT,
    batch_number VARCHAR(64) NOT NULL,
    manufacture_date DATE NOT NULL,
    expiration_date DATE,
    initial_quantity NUMERIC(14, 3) NOT NULL CHECK (initial_quantity > 0),
    current_quantity NUMERIC(14, 3) NOT NULL CHECK (current_quantity >= 0),
    qc_status VARCHAR(30) NOT NULL DEFAULT 'UNDER_CONTROL' CHECK (qc_status IN ('UNDER_CONTROL', 'ACCEPTED', 'REJECTED_QUARANTINE', 'SCRAPPED')),
    barcode VARCHAR(64) NOT NULL UNIQUE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_batch_quantities CHECK (current_quantity <= initial_quantity)
);

-- 11. Протоколы входного контроля ОТК
CREATE TABLE warehouse.qc_protocol (
    id BIGSERIAL PRIMARY KEY,
    batch_id BIGINT NOT NULL UNIQUE REFERENCES warehouse.batch(id) ON DELETE RESTRICT,
    inspector_user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE RESTRICT,
    protocol_number VARCHAR(64) NOT NULL UNIQUE,
    certificate_number VARCHAR(128) NOT NULL,
    certificate_file_path VARCHAR(512),
    verdict VARCHAR(20) NOT NULL CHECK (verdict IN ('PASSED', 'FAILED')),
    inspection_date TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    notes TEXT
);

-- 12. Баланс остатков по ячейкам (Location Balance)
CREATE TABLE warehouse.location_balance (
    id BIGSERIAL PRIMARY KEY,
    cell_id BIGINT NOT NULL REFERENCES warehouse.storage_cell(id) ON DELETE RESTRICT,
    batch_id BIGINT NOT NULL REFERENCES warehouse.batch(id) ON DELETE RESTRICT,
    physical_quantity NUMERIC(14, 3) NOT NULL CHECK (physical_quantity >= 0),
    reserved_quantity NUMERIC(14, 3) NOT NULL DEFAULT 0 CHECK (reserved_quantity >= 0),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_cell_batch UNIQUE (cell_id, batch_id),
    CONSTRAINT chk_physical_gte_reserved CHECK (physical_quantity >= reserved_quantity)
);

-- 13. Требование-накладная на отпуск цехам (форма М-11)
CREATE TABLE warehouse.issue_request (
    id BIGSERIAL PRIMARY KEY,
    request_number VARCHAR(64) NOT NULL UNIQUE,
    department_id INT NOT NULL REFERENCES warehouse.department(id) ON DELETE RESTRICT,
    production_order VARCHAR(64) NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT', 'SUBMITTED', 'RESERVED', 'PICKING', 'ISSUED', 'CANCELED')),
    created_by_user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE RESTRICT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    issued_at TIMESTAMP WITH TIME ZONE
);

-- 14. Строка требования
CREATE TABLE warehouse.request_item (
    id BIGSERIAL PRIMARY KEY,
    request_id BIGINT NOT NULL REFERENCES warehouse.issue_request(id) ON DELETE CASCADE,
    sku_id BIGINT NOT NULL REFERENCES warehouse.sku(id) ON DELETE RESTRICT,
    requested_quantity NUMERIC(14, 3) NOT NULL CHECK (requested_quantity > 0),
    allocated_quantity NUMERIC(14, 3) NOT NULL DEFAULT 0 CHECK (allocated_quantity >= 0),
    issued_quantity NUMERIC(14, 3) NOT NULL DEFAULT 0 CHECK (issued_quantity >= 0),
    CONSTRAINT chk_allocated_le_requested CHECK (allocated_quantity <= requested_quantity),
    CONSTRAINT chk_issued_le_allocated CHECK (issued_quantity <= allocated_quantity)
);

-- 15. Детализация резервов по ячейкам под строку требования
CREATE TABLE warehouse.request_allocation (
    id BIGSERIAL PRIMARY KEY,
    request_item_id BIGINT NOT NULL REFERENCES warehouse.request_item(id) ON DELETE CASCADE,
    location_balance_id BIGINT NOT NULL REFERENCES warehouse.location_balance(id) ON DELETE RESTRICT,
    quantity NUMERIC(14, 3) NOT NULL CHECK (quantity > 0),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 16. Журнал складских проводок (Аудит движения ТМЦ)
CREATE TABLE warehouse.stock_movement_log (
    id BIGSERIAL PRIMARY KEY,
    batch_id BIGINT NOT NULL REFERENCES warehouse.batch(id) ON DELETE RESTRICT,
    source_cell_id BIGINT REFERENCES warehouse.storage_cell(id) ON DELETE RESTRICT,
    target_cell_id BIGINT REFERENCES warehouse.storage_cell(id) ON DELETE RESTRICT,
    quantity NUMERIC(14, 3) NOT NULL CHECK (quantity > 0),
    movement_type VARCHAR(30) NOT NULL CHECK (movement_type IN ('RECEIPT_PUTAWAY', 'INTERNAL_TRANSFER', 'PRODUCTION_ISSUE', 'INVENTORY_ADJUSTMENT', 'SCRAP')),
    document_ref VARCHAR(64) NOT NULL,
    performed_by_user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE RESTRICT,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 17. Описи инвентаризации (ИНВ-3)
CREATE TABLE warehouse.inventory_sheet (
    id BIGSERIAL PRIMARY KEY,
    sheet_number VARCHAR(64) NOT NULL UNIQUE,
    zone_id INT NOT NULL REFERENCES warehouse.warehouse_zone(id) ON DELETE RESTRICT,
    status VARCHAR(20) NOT NULL DEFAULT 'IN_PROGRESS' CHECK (status IN ('IN_PROGRESS', 'REVIEW', 'APPROVED')),
    created_by_user_id BIGINT NOT NULL REFERENCES warehouse.app_user(id) ON DELETE RESTRICT,
    start_date TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    end_date TIMESTAMP WITH TIME ZONE
);

-- 18. Позиции инвентаризационной описи
CREATE TABLE warehouse.inventory_item (
    id BIGSERIAL PRIMARY KEY,
    sheet_id BIGINT NOT NULL REFERENCES warehouse.inventory_sheet(id) ON DELETE CASCADE,
    cell_id BIGINT NOT NULL REFERENCES warehouse.storage_cell(id) ON DELETE RESTRICT,
    batch_id BIGINT NOT NULL REFERENCES warehouse.batch(id) ON DELETE RESTRICT,
    expected_quantity NUMERIC(14, 3) NOT NULL CHECK (expected_quantity >= 0),
    counted_quantity NUMERIC(14, 3) NOT NULL CHECK (counted_quantity >= 0),
    discrepancy NUMERIC(14, 3) GENERATED ALWAYS AS (counted_quantity - expected_quantity) STORED
);
```

### 4. Индексный план оптимизации производительности

Для обеспечения регламентного времени отклика системы ($\le 1{,}5$ с) создаются специализированные B-Tree индексы под высоконагруженные запросы:

```sql
-- 1. Поиск свободных остатков партий по SKU для FIFO-аллокации
CREATE INDEX idx_batch_sku_qc ON warehouse.batch(sku_id, qc_status) 
WHERE qc_status = 'ACCEPTED' AND current_quantity > 0;

-- 2. Поиск доступных ячеек с годным остатком
CREATE INDEX idx_loc_balance_batch ON warehouse.location_balance(batch_id) 
WHERE (physical_quantity - reserved_quantity) > 0;

-- 3. Быстрый поиск по штрихкоду ячейки и партии (для терминалов сбора данных)
CREATE INDEX idx_cell_address ON warehouse.storage_cell(address_code);
CREATE INDEX idx_batch_barcode ON warehouse.batch(barcode);

-- 4. Выборка активных требований цехов
CREATE INDEX idx_issue_req_status_dept ON warehouse.issue_request(department_id, status);

-- 5. Выборка журнала проводок за период по партии
CREATE INDEX idx_movement_batch_time ON warehouse.stock_movement_log(batch_id, created_at DESC);
```

### 5. Выводы по физическому проектированию

1. Скрипт миграции полностью автономен, строго детерминирован и готов к развёртыванию в CI/CD-пайплайне через инструмент Flyway.
2. Встроенные ограничения `CHECK` и вычисляемые столбцы (`GENERATED ALWAYS AS`) исключают появление логических аномалий на уровне самой СУБД независимо от клиентского кода.
3. Индексный план ориентирован на ускорение ключевых сценариев: сканирование ТСД и подбор партий алгоритмом FIFO.
