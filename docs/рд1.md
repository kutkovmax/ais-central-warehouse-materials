## Документ РД-01. Спецификация межмодульного взаимодействия и REST API контракты

**Шифр документа:** АИС-ЦС-2026-РД-01  
**Стадия по ГОСТ 34.601-90:** Рабочая документация  
**Версия:** 1.0 (Утверждённая)  
**Формат спецификации:** OpenAPI 3.0 / JSON REST API  

---

### 1. Общие принципы проектирования API

1. **Транспорт и безопасность:** Протокол HTTPS (TLS 1.3), порт 443. Передача маркера доступа в заголовке `Authorization: Bearer <JWT-Token>`.
2. **Формат обмена данными:** `application/json; charset=UTF-8`.
3. **Идемпотентность:** Для всех мутирующих запросов (`POST`, `PUT`) с мобильных терминалов сбора данных (ТСД) обязателен заголовок `X-Idempotency-Key: <UUID>` во избежание дублирования складских проводок при сбоях сети.
4. **Стандартные коды возврата:**
   * `200 OK` — операция выполнена успешно;
   * `201 Created` — сущность успешно создана;
   * `400 Bad Request` — ошибка валидации входных данных (DTO Bean Validation);
   * `401 Unauthorized` / `403 Forbidden` — отказ в доступе по ролевой модели RBAC;
   * `409 Conflict` — конфликт параллельного изменения (нарушение условий блокировок);
   * `422 Unprocessable Entity` — нарушение бизнес-правил (например, попытка отпустить партию без статуса `ACCEPTED`).

### 2. Спецификация эндпоинтов подсистемы приёмки и входного контроля (ВК)

#### 2.1. Регистрация входящей поставки (Оформление приходного ордера М-4)
* **Метод и URI:** `POST /api/v1/receipts`
* **Роли доступа:** `ROLE_STOREKEEPER_RECEIVING`, `ROLE_ADMIN`
* **Описание:** Создаёт заголовок приходного ордера, регистрирует партии ТМЦ, присваивает статус `UNDER_CONTROL` и временно помещает их в Зону Q (карантин).

**Тело запроса (Request JSON):**
```json
{
  "docNumber": "М4-2026-00842",
  "supplierInn": "3528000413",
  "incomingInvoiceNum": "94812",
  "incomingInvoiceDate": "2026-05-10",
  "targetQuarantineCell": "Q-01-01-1-01",
  "items": [
    {
      "article": "МЕТ-КР-40Х-50",
      "batchNumber": "Пл. 84210",
      "manufactureDate": "2026-04-20",
      "expirationDate": null,
      "quantity": 4.250
    },
    {
      "article": "ЛКМ-ЭП-0199",
      "batchNumber": "П-884",
      "manufactureDate": "2026-05-01",
      "expirationDate": "2026-11-01",
      "quantity": 400.000
    }
  ]
}
```

**Тело ответа (Response JSON 201 Created):**
```json
{
  "receiptOrderId": 842,
  "docNumber": "М4-2026-00842",
  "status": "IN_INSPECTION",
  "createdBatches": [
    {
      "batchId": 19041,
      "article": "МЕТ-КР-40Х-50",
      "barcode": "BATCH-20260512-19041",
      "qcStatus": "UNDER_CONTROL",
      "allocatedCell": "Q-01-01-1-01"
    },
    {
      "batchId": 19042,
      "article": "ЛКМ-ЭП-0199",
      "barcode": "BATCH-20260512-19042",
      "qcStatus": "UNDER_CONTROL",
      "allocatedCell": "Q-01-01-1-01"
    }
  ]
}
```

#### 2.2. Фиксация решения входного контроля ОТК
* **Метод и URI:** `POST /api/v1/qc/inspect`
* **Роли доступа:** `ROLE_QC_INSPECTOR`, `ROLE_ADMIN`
* **Описание:** Прикрепляет протокол испытаний к партии и переводит статус в `ACCEPTED` либо `REJECTED_QUARANTINE`.

**Тело запроса (Request JSON):**
```json
{
  "batchId": 19041,
  "protocolNumber": "ПК-05/182",
  "certificateNumber": "СЕРТ-СС-90412",
  "certificateFilePath": "/storage/certs/2026/05/sert_90412.pdf",
  "verdict": "PASSED",
  "notes": "Твёрдость 217 HB. Геометрия в допуске ГОСТ 2590-2006."
}
```

**Тело ответа (Response JSON 200 OK):**
```json
{
  "batchId": 19041,
  "qcStatus": "ACCEPTED",
  "inspectionDate": "2026-05-13T09:15:30Z",
  "message": "Партия допущена к размещению в основную зону хранения."
}
```

### 3. Спецификация эндпоинтов подсистемы адресного размещения и ТСД

#### 3.1. Запрос рекомендованной ячейки для размещения
* **Метод и URI:** `GET /api/v1/storage/suggest-cell?batchId=19041`
* **Роли доступа:** `ROLE_STOREKEEPER_RECEIVING`, `ROLE_STOREKEEPER_PICKING`
* **Описание:** Запускает алгоритм АЛГ-01 (подбор оптимальной ячейки с учётом массы, объёма и зоны).

**Тело ответа (Response JSON 200 OK):**
```json
{
  "batchId": 19041,
  "article": "МЕТ-КР-40Х-50",
  "batchWeightKg": 4250.0,
  "suggestedCell": {
    "cellId": 104,
    "addressCode": "A-02-05-1-01",
    "zoneCode": "A",
    "freeCapacityKg": 5750.0,
    "cellStatus": "PARTIALLY_OCCUPIED"
  }
}
```

#### 3.2. Подтверждение размещения партии по результатам сканирования ТСД
* **Метод и URI:** `POST /api/v1/storage/confirm-putaway`
* **Роли доступа:** `ROLE_STOREKEEPER_RECEIVING`, `ROLE_STOREKEEPER_PICKING`
* **Описание:** Валидирует сканирование штрихкодов партии и ячейки, перемещает остаток из карантина в целевую ячейку и регистрирует проводку в `stock_movement_log`.

**Тело запроса (Request JSON):**
```json
{
  "batchBarcode": "BATCH-20260512-19041",
  "cellAddressCode": "A-02-05-1-01",
  "confirmedQuantity": 4.250
}
```

**Тело ответа (Response JSON 200 OK):**
```json
{
  "movementId": 55420,
  "batchId": 19041,
  "sourceCell": "Q-01-01-1-01",
  "targetCell": "A-02-05-1-01",
  "quantity": 4.250,
  "status": "COMPLETED",
  "timestamp": "2026-05-13T10:40:12Z"
}
```

### 4. Спецификация эндпоинтов подсистемы требований цехов и FIFO-отпуска

#### 4.1. Создание электронного требования цеха (Форма М-11)
* **Метод и URI:** `POST /api/v1/issues/requests`
* **Роли доступа:** `ROLE_SHOP_MASTER`, `ROLE_ADMIN`
* **Описание:** Создаёт требование М-11 под конкретный заказ цеха (МЦ-1, СЦ-2, ЦПО).

**Тело запроса (Request JSON):**
```json
{
  "departmentCode": "SC-2",
  "productionOrder": "ЦНС-180-1400",
  "items": [
    {
      "article": "ПОДШ-7312-В",
      "requestedQuantity": 4.000
    },
    {
      "article": "МЕТИЗ-Б12-80",
      "requestedQuantity": 48.000
    }
  ]
}
```

**Тело ответа (Response JSON 201 Created):**
```json
{
  "requestId": 1104,
  "requestNumber": "М11-2026-01104",
  "department": "Сборочный цех № 2",
  "status": "SUBMITTED",
  "createdAt": "2026-05-14T07:30:00Z"
}
```

#### 4.2. Аллокация и резервирование партий по алгоритму FIFO
* **Метод и URI:** `POST /api/v1/issues/requests/{requestId}/allocate`
* **Роли доступа:** `ROLE_STOREKEEPER_PICKING`, `ROLE_WAREHOUSE_HEAD`, `ROLE_ADMIN`
* **Описание:** Запускает алгоритм АЛГ-02. Накладывает блокировку `FOR UPDATE` на остатки и резервирует годные партии.

**Тело ответа (Response JSON 200 OK):**
```json
{
  "requestId": 1104,
  "status": "RESERVED",
  "allocatedItems": [
    {
      "article": "ПОДШ-7312-В",
      "requestedQuantity": 4.000,
      "allocatedQuantity": 4.000,
      "allocations": [
        {
          "batchId": 18402,
          "cellAddressCode": "B-01-04-2-01",
          "reservedQuantity": 4.000
        }
      ]
    },
    {
      "article": "МЕТИЗ-Б12-80",
      "requestedQuantity": 48.000,
      "allocatedQuantity": 48.000,
      "allocations": [
        {
          "batchId": 18512,
          "cellAddressCode": "B-04-12-3-02",
          "reservedQuantity": 48.000
        }
      ]
    }
  ]
}
```

#### 4.3. Подтверждение выдачи ТМЦ в цех и списание баланса
* **Метод и URI:** `POST /api/v1/issues/requests/{requestId}/complete-issue`
* **Роли доступа:** `ROLE_STOREKEEPER_PICKING`
* **Описание:** Списывает физический остаток из ячеек склада, переводит требование в статус `ISSUED`, формирует подписанную электронную форму М-11.

**Тело ответа (Response JSON 200 OK):**
```json
{
  "requestId": 1104,
  "status": "ISSUED",
  "issuedAt": "2026-05-14T11:20:15Z",
  "completedBy": "Ковалёв Д.С.",
  "receivedBy": "Кузнецов А.М.",
  "message": "Материалы списаны со склада и переданы в СЦ-2."
}
```

### 6. Выводы по разделу

1. Специфицированный набор REST-интерфейсов полностью покрывает бизнес-процессы, описанные в BPMN (`CA-3.md`) и дереве функций (`CA-4.md`).
2. Применение токенов JWT и аннотаций `@PreAuthorize` обеспечивает надёжную защиту на уровне контроллеров в соответствии с матрицей RACI (`5.md`).
3. Использование заголовка `X-Idempotency-Key` защищает базу данных от коллизий при нестабильном Wi-Fi покрытии на рампе и удалённых складах.
