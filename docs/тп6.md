### 1. Назначение и методологические основы

Настоящий документ регламентирует программную архитектуру АИС «Склад-МехПром» с использованием визуальной нотации **C4 Model** (Context, Containers, Components, Code), адаптированной под требования ГОСТ 34.201-2020 и ГОСТ 34.602-2020.

Модель обеспечивает сквозную прозрачность архитектурных решений от верхнеуровневого окружения завода до структуры Java-пакетов и классов Spring Boot фреймворка.

#### Назначение ключевых сервисных компонентов:
1. **`ReceiptService`:** Регистрация входящих документов (М-4), создание партий со статусом `UNDER_CONTROL`, привязка к карантинной Зоне Q.
2. **`QcInspectionComponent`:** Проверка прав инженера ОТК, привязка файлов сертификатов, атомарный перевод статуса партии в `ACCEPTED` или `REJECTED_QUARANTINE`.
3. **`PlacementEngine`:** Реализация алгоритма АЛГ-01 (расчёт допустимых ячеек по массе $M_{\max}$, объёму $V_{\max}$ и ABC-рангу).
4. **`FifoAllocationEngine`:** Реализация алгоритма АЛГ-02 (выборка партий по FIFO/FEFO с наложением пессимистической блокировки `SELECT FOR UPDATE`).
5. **`StockAuditService`:** Фиксация каждой физической манипуляции в таблице `stock_movement_log` с запретом модификации (`APPEND-ONLY`).

### 5. Уровень 4: Детализация исходного кода (Code Structure)

Структура пакетов Java-приложения соответствует архитектурному стилю **Domain-Driven Modular Monolith**:

```
ru.mechprom.warehouse/
├── config/
│   ├── SecurityConfig.java           // Настройки JWT, CORS, RBAC URL-фильтров
│   └── DatabaseConfig.java           // Настройки пула HikariCP, JPA Auditing
├── domain/
│   ├── nsi/                          // Подсистема НСИ (Sku, StorageCell, Zone)
│   ├── receipt/                      // Подсистема приёмки (ReceiptOrder, Batch)
│   ├── quality/                      // Подсистема ОТК (QcProtocol, Certificate)
│   ├── storage/                      // Баланс ячеек (LocationBalance, MovementLog)
│   └── issue/                        // Подсистема отпуска (IssueRequest, Allocation)
├── engine/
│   ├── FifoAllocationEngine.java     // Реализация алгоритма FIFO-резерва
│   └── OptimalCellPlacementEngine.java // Реализация алгоритма подбора ячейки
├── repository/                       // Интерфейсы Spring Data JPA
├── web/
│   ├── dto/                          // Data Transfer Objects с валидацией JSR-380
│   └── controller/                   // REST контроллеры веб-АРМ и ТСД
└── WarehouseApplication.java         // Точка входа Spring Boot
```

### 7. Выводы по разделу

1. Выбранный архитектурный стиль модульного монолита в рамках модели C4 исключает затраты на оркестрацию микросервисов и гарантирует строгую согласованность данных.
2. Изоляция прикладных механизмов (алгоритмы FIFO и подбора ячеек вынесены в обособленный пакет `engine`) обеспечивает независимое модульное тестирование (Unit Testing) с покрытием кода не менее 80%.
3. Развёртывание в среде Docker Compose на базе сертифицированной ОС Astra Linux удовлетворяет требованиям информационной безопасности машиностроительного предприятия.
