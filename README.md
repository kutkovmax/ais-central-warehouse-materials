# АС центрального склада материалов

Проект автоматизированной системы центрального склада материалов. Система должна поддерживать складской учёт, движение материалов по партиям и местам хранения, заявки производственных подразделений, инвентаризацию и обмен с 1С:ERP.

## Состояние проекта

Собран первый backend-MVP: FastAPI, PostgreSQL, модели материалов/мест хранения/партий/приёмок/движений и API для создания справочников, проведения приёмки и чтения остатков. Frontend, заявки, инвентаризация и обмен с 1С:ERP пока следующие этапы.

Исходный документ: [Техническое задание](docs/Техническое_задание_АС_центрального_склада.docx).

## Оценка моделей в ТЗ

| Модель | Что есть | Что требуется усилить |
| --- | --- | --- |
| Функциональная | Разделы назначения и требований, роли, таблица `FR-01`–`FR-12`, критерии приёмки | Связать каждое FR с актором, API/сервисом, экраном, ошибками и тестом |
| Информационная | Описаны PostgreSQL, интеграция с 1С:ERP и перечень основных таблиц/сущностей | Добавить ER-диаграмму, кардинальности, статусы, ограничения, справочники, историю и правила расчёта остатков |
| Процессная | Есть описание складских операций, AS-IS/TO-BE направления, этапы работ и сценарии использования | Добавить BPMN/диаграммы последовательности для ключевых процессов и явно описать переходы статусов и исключения |

Итог: все три слоя в ТЗ представлены, но полноценными моделями их пока считать нельзя. Функциональный слой наиболее проработан. Информационный слой представлен логической заготовкой схемы БД. Процессный слой требует отдельного графического и формального описания.

## Предметная область

Ключевые объекты:

- организационные единицы и пользователи;
- поставщики, единицы измерения и группы материалов;
- материалы, партии, зоны и места хранения;
- документы приёмки и строки приёмки;
- производственные заявки и строки заявок;
- складские операции и строки операций;
- движения и остатки;
- распределение материалов по заявкам;
- документы и строки инвентаризации.

Ключевые процессы:

1. приёмка материала и размещение по местам хранения;
2. создание, согласование и исполнение заявки;
3. резервирование, подбор и выдача материала;
4. возврат и обратное размещение;
5. внутреннее перемещение;
6. инвентаризация и оформление расхождений;
7. списание;
8. обмен нормативно-справочной и операционной информацией с 1С:ERP.

## Архитектурные ориентиры

- веб-приложение для рабочих мест склада и смежных подразделений;
- PostgreSQL для транзакционных данных и журнала движений;
- интеграционный контур с 1С:ERP;
- серверная валидация прав и бизнес-правил;
- аудит действий пользователей и изменений документов;
- идемпотентность складских операций и интеграционных сообщений;
- воспроизводимый остаток на основании движений, а не ручного редактирования.

## Ближайшие артефакты перед разработкой

1. Контекстная диаграмма системы и границы интеграции с 1С:ERP.
2. Матрица ролей и разрешений.
3. ER-диаграмма с ключами, связями и ограничениями.
4. BPMN или эквивалентные схемы для приёмки, выдачи, перемещения и инвентаризации.
5. Таблица переходов статусов документов и складских операций.
6. Матрица трассируемости `FR-NN` → реализация → тест приёмки.
7. Контракт интеграции: форматы сообщений, идентификаторы, повторы, ошибки и reconciliation.

Подробные правила для разработчиков и агентов находятся в [AGENTS.md](AGENTS.md). При появлении исходного кода сюда следует добавить команды установки зависимостей, запуска, миграций, тестов и локального стенда.

## Запуск MVP

Требуются Docker и Docker Compose.

```powershell
docker compose up --build
```

После запуска:

- проверка состояния: `GET http://localhost:8000/health`;
- Swagger UI: `http://localhost:8000/docs`;
- API материалов: `/api/v1/materials`;
- API мест хранения: `/api/v1/storage-locations`;
- проведение приёмки: `POST /api/v1/receipts`;
- остатки: `GET /api/v1/stock`.

Текущий bootstrap создаёт таблицы при старте приложения. Перед промышленной эксплуатацией его нужно заменить на Alembic-миграции, добавить авторизацию, аудит, полноценные документы процессов и интеграционный outbox.
